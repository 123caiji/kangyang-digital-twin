二、体积是怎么砍下来的

踩过的坑：第一版只改「注册哪些组件」，保留 import { ElButton } from 'element-plus' 根路径导入 —— JS 从 908.81 kB 只降到 906.98 kB，几乎没动。 根因是 es/index.mjs 是 301 行的 barrel，只要有一处根导入，整棵组件树就进图， 而组件顶层调用的 withInstall() 未标 /*#__PURE__*/，Rollup 摇不掉。 正解是两头收口：组件走自身深路径 + 所有业务引用统一到单一入口。

桌面 166 不是缺陷。那是拿触屏 44px 标准去量鼠标界面的结果； 桌面已无任何低于 24px 的元素。桌面追求 44px 会显著撑高表格密度，属有意取舍。
另外，本期修正了触控目标的测量口径（按真实命中祖先判定，不再把组件库内部零件单算）， 因此桌面端前后数字不同源，不可直接相减。

四、为什么桌面没有回归

新增的 44px 规则整块包在 (max-width: 1023.98px) ∩ (pointer: coarse) 内。审计脚本每页都输出指针类型， 1024 / 1440 两档实测均报告 [鼠标] —— 媒体查询不匹配，新规则在桌面完全不参与级联。 这是可验证的事实，不是推断。

五、交互体验补强

  • 路由过渡：0.18s 纯透明度淡入淡出。刻意不做位移 —— canvas 与绝对定位图层下，transform 会促成额外合成层并让 ECharts 尺寸测量出现亚像素抖动。
  • 懒加载进度条：顶部 2px 渐变条，延迟 120ms 出现（命中缓存时不闪）。用无限动画表达「进行中」，不伪造 0→90% 的假进度 —— 真实下载进度本来就取不到。
  • 客户端路由实测：8 组侧栏点击跳转，逐项断言 DOM 节点数 / opacity / 标题 / 路径，全部正常且 0 错误。
  • 时钟重渲染下沉：拆分 LiveClock.vue，原先每秒触发整个 Layout（含 10 项侧栏）重渲染，现在只有叶子组件重渲染。
  • 链接按钮抬到 24px：原先 el-button is-link 仅 20px 高，低于 WCAG 下限，养老场景下对长者尤其不友好。

九、已知限制与建议

  • 桌面 44px 未追求，属有意取舍（点击精度 vs 表格密度），维持 24px 下限。
  • vendor-echarts 1.48MB 仍是最大 chunk。若继续优化，建议改 echarts/core 按需注册，预估同样接近一半下降空间 —— 本期未动，因涉及 6 个页面 import 方式改动，风险量不同。
  • 尚未发布线上。dist/ 仍是旧产物，新构建在 dist-after-element/。发布前建议上线比对一轮公网首屏（此前记录约 10.3s）确认收益。
  • 触控口径本期已变更，历史报告不可与新报告直接相减，跨期对比请统一用 [触屏]/[鼠标] 标注后的数据。
