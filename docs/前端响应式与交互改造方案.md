# 康养数字孪生平台 · 前端响应式与交互体验改造方案

> 版本 v1.0 ｜ 2026-09-28 ｜ 角色：前端开发工程师
> 依据：无头浏览器实测（`.audit/before/report.json`，36 组视口×页面样本）

---

## 一、结论先行

**当前前端只适配了桌面横屏，移动端处于「不可用」状态，不是「不美观」。**

三条铁证（375×812 实测）：

| 现象 | 实测值 |
|---|---|
| 侧边栏吃掉视口宽度 | 固定 220px = **58.7%**，且**无法收起**（无汉堡按钮） |
| 图表实际可用宽度 | 健康监测页 canvas **89px**（桌面端同页 557px） |
| 页面纵向滚动 | `body.overflow-y: hidden` + `.content` 不可滚 → 超出内容**直接被裁掉** |

对应的后果：健康监测页 KPI 卡片被压成 155px 宽竖排、图表标题「健康监测·IoT实时数据」逐字换行；数据管理页表格只剩「操作」列可见、分页器被截断；3D 大屏左面板覆盖整屏、**3D 场景完全看不见**、顶部导航碎成右侧竖排文字。

改造方向明确：**以桌面端为基准不动，新增移动端形态**，而不是把桌面布局等比缩小。

## 二、现状诊断（实测证据）

### 2.1 测试方法

### 2.3 问题归因（六类）

**① 断点体系不完整** — 全项目仅 9 处 `@media`，只有 `1100px` / `1000px` 两档，且只做「两列 → 一列」。**没有 768px / 480px 移动端断点**，没有 `pointer: coarse` 触控判定。

**② 布局骨架无移动形态** — `Layout.vue` 的 `.sider` 写死 `width: 220px; flex-shrink: 0`，没有折叠态、没有抽屉、没有汉堡按钮。

**③ 全局滚动被锁死** — `global.scss` 中 `body { overflow: hidden }` 叠加 `.content { overflow: hidden }`。桌面大屏思路，但在手机上等于「内容消失」，且 `.page-scroll` 之外没有任何兜底。

**④ 尺寸硬编码** — 工具栏 `style="width: 180px / 220px"` 内联写死，`el-dialog width="560px"`，`Predict` 用 `grid-template-columns: 440px 1fr`。375px 视口下 560px 的弹窗必然溢出。

**⑤ 触摸与手势缺失** — `Room3D.vue` 用 `pointerdown/move/up` 拖拽旋转（触屏勉强可用），但：画布**无 `touch-action` 声明** → 拖拽会与页面滚动/双指缩放抢事件；缩放只绑了 `wheel` 滚轮 → **触屏无滚轮，移动端根本无法缩放**；键盘 `WASD/QE` 控制在手机上无替代入口。

**⑥ 无障碍与反馈缺失** — 无 `:focus-visible` 样式、无 `aria-label`、大屏导航用 `<a href="javascript:;">`（屏幕阅读器不可读）、无 `prefers-reduced-motion` 降级、无 `100dvh`（移动浏览器地址栏造成视口跳动）；各页 `onMounted` 直接 `await`，网络慢时白屏，**无骨架屏 / 空状态 / 失败重试**。

## 三、目标与验收标准

| 维度 | 指标 | 目标 | 当前 |
|---|---|---|---|
| 响应式 | 横页面横向溢出元素数 | 0（375 / 768 / 1024 / 1440 全档） | 375px 档 46 个 |
| 响应式 | 移动端内容区可纵向滚动 | 全部页面可滚 | 0/9 |
| 触控 | 交互元素高度 ≥44px | 100% | 最低 375px 档 31 个不达标 |
| 图可读性 | 375px 图表容器宽度 | ≥ 343px（视口 - 32px） | 89px |
| 无障碍 | 键盘可达 + `:focus-visible` + `aria` | 主流程全覆盖 | 无 |
| 反馈 | 加载/空/错误态 | 全部数据页覆盖 | 无 |
| **不回退** | 1440px 布局与观感 | 与改造前一致 | 基准 |

## 四、断点策略

采用业界通行的移动优先分层，落在 SCSS mixin 中统一调用：

| 名称 | 区间 | 布局形态 |
|---|---|---|
| `mobile` | < 768px | 侧栏 → 抽屉；数据表 → 卡片列表；弹窗 → 全屏 |
| `tablet` | 768 – 1023px | 侧栏 → 64px 图标栏；双列栅格保留 |
| `desktop` | ≥ 1024px | 现有布局（220px 侧栏 + 多列栅格） |

补充规则：
- `(pointer: coarse)` → 触控目标升到 44px、3D 显示虚拟控制按钮
- `(prefers-reduced-motion: reduce)` → 关闭装饰性动画
- 高度维度用 `100dvh` 替代 `100vh`，避免移动浏览器地址栏收放导致跳动

## 五、分阶段实施方案

### P0 · 地基（新增为主，不改现有视觉）

| 项 | 文件 | 内容 |
|---|---|---|
| 设计令牌 | `src/styles/tokens.scss`（新） | 断点值、间距阶梯、触控最小尺寸、动效时长、`--app-gutter: clamp(12px, 2.4vw, 24px)` |
| 断点 mixin | `src/styles/responsive.scss`（新） | `@mixin mobile / tablet / desktop / coarse-pointer`，经 Vite `additionalData` 全局注入，scoped 样式可直接用 |
| 断点 composable | `src/composables/useBreakpoint.js`（新） | `isMobile / isTablet / isDesktop` 响应式布尔（仅在必须走 JS 时用：表格形态切换、弹窗全屏、画布尺寸） |
| 全局增补 | `src/styles/global.scss` | `100dvh`、`:focus-visible` 描边、`prefers-reduced-motion`、`.sr-only`、窄屏细滚动条、`overscroll-behavior: contain` |

### P1 · 布局骨架（最高杠杆）

`src/views/Layout.vue`

- ≥1024px：保持 220px 固定侧栏（**视觉不变**）
- 768–1023px：侧栏收成 64px 图标栏，悬停/聚焦浮层显示文字
- <768px：侧栏转 `el-drawer` 抽屉，顶栏出现汉堡按钮，遮罩点击关闭；抽屉打开时锁 body 滚动
- 顶栏时间在 <560px 隐藏（释放标题空间）
- `.content` 由 `overflow: hidden` 改为按档位 `auto`；`body` 放开纵向滚动
- 菜单项 `min-height: 44px`

### P2 · 3D 大屏（`Dashboard.vue` + `Room3D.vue`，最难点）

- **结构分档**：桌面保持现有悬浮 HUD 叠加（不动观感）；<1100px 改文档流 → 3D 画布占 `46dvh` 固定区，数据面板转为下方可滚卡片区；<768px 详情面板改底部抽屉
- **3D 手势**：画布加 `touch-action: none`；新增**双指捏合缩放**（多点 pointer 距离映射到 `orbitRadius`）；`pointer: coarse` 时显示虚拟方向/缩放按钮组，作为键盘 `WASD/QE` 的移动端替代
- **降级**：WebGL 不可用时展示静态示意图 + 提示，不再黑屏
- **AI 面板**：<768px 转底部抽屉，`max-height: 72dvh`，底部留 `env(safe-area-inset-bottom)`
- 顶部导航 <900px 折叠进抽屉

### P3 · 数据与表单页

- `DataManage.vue`：<768px 工具栏纵向堆叠（清除内联固定宽度）；**表格转卡片列表**（每行一张卡片，操作按钮置底）；分页精简为 `prev/pager/next`；弹窗全屏
- `UserManage.vue` / `DbSettings.vue` / `Predict.vue`：同类处理；`Predict` 的 `440px 1fr` 栅格与 `88px 1fr 56px` 滑块行按档位重排
- 统一弹窗策略：`isMobile ? 'fullscreen' : '560px'`；表单 `label-position` 在移动端改顶对齐

### P4 · 图表页

- `ChartPanel.vue`：`window.resize` 升级为 `ResizeObserver`（侧栏折叠、抽屉开合引起的容器宽度变化也能触发重绘）
- ECharts option 按断点降级：窄屏图例改滚动/隐藏、`grid` 收紧、轴标签旋转与 `interval` 抽稀、KPI 卡 2 列
- 图表容器设最小高度与最小宽度，杜绝 89px 宽度重现

### P5 · 交互体验与无障碍

- 骨架屏（`el-skeleton`）、空状态（`el-empty`）、失败重试（axios 拦截器已统一 toast，补重试入口）
- 微交互：过渡曲线、按钮 loading、防重复提交
- 无障碍：`:focus-visible`、`aria-label`、Esc 关闭弹层、Tab 顺序、`<a href="javascript:;">` 改语义化 `button`
- 触控目标全部 ≥44px

### P6 · 性能与验收

- Element Plus / ECharts 按需引入（当前 `main.js` 全量注册 Element Plus + 全量图标）
- 复跑 `scripts/responsive-audit.mjs --tag after`，与 `before` 逐项对比，输出对比报告

## 六、不变式与风险

**不变式（红线）**

1. 1440px 桌面端布局、配色、玻璃拟态观感**保持不变**——这是毕设演示的主场景
2. `--sc-*` CSS 变量与 `themeStore.applyCss()` 运行时换肤机制**不能破坏**（样式设置页依赖它）
3. 后端 API 契约不变，纯前端改造
4. 每个阶段结束后复跑 audit，用数据证明「新达标项 + 零回退」

**风险与对策**

| 风险 | 对策 |
|---|---|
| 3D 大屏结构分档改动大，易破坏桌面观感 | 桌面档 CSS 分支保持原样，新增分支只作用于 `<1100px`；audit 对比 1440px 截图逐页校验 |
| 表格转卡片列表导致功能缺失 | 保留完整列数据于卡片内，仅重排不裁剪；导出/编辑/删除能力不减 |
| 抽屉与 Element Plus 组件层级冲突 | 统一 `z-index` 阶梯令牌，抽屉层级低于全局消息提示 |
| 移动端 3D 性能不足（低端机） | WebGL 能力检测 + 降级示意图；`renderer.setPixelRatio` 上限按档位收紧 |

### 📌 已知问题记录

1. 实测脚手架初版用 `networkidle2` 等待，图表 / 3D 页存在持续请求会导致偶发超时误报 → 已改为 `domcontentloaded` + 固定沉降时间，复测 0 失败。
2. 脚手架 `collector` 初版用 `viewport` 字段名，与外部 `viewport: width` 冲突导致字段被覆盖 → 已改名 `vp`。
3. **`<style scoped>` 里写 SCSS 会静默失效。** Vue SFC 默认按纯 CSS 处理样式块，`@include` 会被浏览器当作未知 at 规则整条丢弃 —— 构建不报错、运行不报错，但整段媒体查询失效。
   本次在 `ChartsOps.vue` 与 `Predict.vue` 各踩到一次（表现为 Predict 仍为 `440px 1fr` 双列，右侧面板被挤出视口，产生 88 个溢出元素）。
   → 已新增守卫 `scripts/check-styles.mjs`：检测纯 CSS 样式块中的 SCSS 语法并报错退出，建议纳入提交前检查。
4. **固定列遮挡失效。** 全局把 `.el-table td` 设为透明后，`fixed="right"` 的操作列无法遮挡其下方横向滚动的内容，文字相互叠加。
   修复要点：选择器必须带上 `td.el-table__cell` 才能压过透明规则（同为 `!important` 时按特异性决胜），且**必须同时覆盖斑马纹与悬停状态** —— 斑马纹规则的特异性最高，只写普通态会导致隔行重新透出。
