## 二、首屏体积：从 1.72MB 砍到 1.06MB

### 问题定位

`main.js` 里是 `app.use(ElementPlus)` 全量注册：

```js
import ElementPlus from 'element-plus'
import 'element-plus/dist/index.css'
app.use(ElementPlus, { locale: zhCn })
```

Element Plus 有 124 个组件，本项目实际只用了 **28 个**。即便路由全部懒加载，
全量注册把整棵组件树和整份 `theme-chalk` 都塞进了主包 —— 路由懒加载只省了业务代码，省不掉组件库。

### 第一次改法失败（值得记一笔）

我先做了一版「看起来正确」的改法：**保留 `import { ElButton } from 'element-plus'` 的根路径导入，只注册用到的组件**。

实测结果：

| | 改前 | 第一次改后 | 变化 |
|---|---|---|---|
| vendor-element.js | 908.81 kB | 906.98 kB | **-1.8 kB** |
| vendor-element.css | 357.67 kB | 174.79 kB | -51% |

CSS 砍了一半，JS 几乎没动。

**原因**：`'element-plus'` 的 ESM 入口 `es/index.mjs` 是一个 301 行的 barrel 文件，
把 124 个组件、全部 hooks、指令、插件一次性 re-export。只要项目里**任何一处**还写着
`import { ElMessage } from 'element-plus'`（当时 `http.js` 和 6 个页面都这么写），
这棵 barrel 就完整进入依赖图；而每个组件模块顶层都调用 `withInstall(xxx)` 且没标 `/*#__PURE__*/`，
Rollup 无法证明其无副作用，于是整棵子树保留。

验证方式：直接在产物里搜未使用组件的名字 —— `ElCascader`、`ElCarousel`、`ElTransfer`、
`ElTimeline`、`ElWatermark`、`ElCountdown` 全部在场，坐实了树摇没生效。

### 正确改法：两头收口

1. **组件改用自身深路径导入**，绕开 barrel：
   `import ElButton from 'element-plus/es/components/button/index.mjs'`
2. **把所有业务引用统一到单一入口** `src/plugins/element.js`，禁止再写 `from 'element-plus'`。

并且加了静态守卫 `scripts/check-element-imports.mjs` 把这条约束固化下来 ——
它会同时检查「模板里用到的 `<el-xxx>` 是否都已注册」和「是否有人绕过了插件入口」。

### 实测结果

| 产物 | 改前 (gzip) | 改后 (gzip) | 降幅 |
|---|---|---|---|
| vendor-element.js | 908.81 kB (292.70) | **444.87 kB (146.94)** | **-51.1% / -49.8%** |
| vendor-element.css | 357.67 kB (47.85) | **167.59 kB (23.10)** | **-53.1% / -51.7%** |
| **首屏 JS 合计** | 1360.84 kB (439.09) | **885.62 kB (289.75)** | **-34.9% / -34.0%** |
| **首屏 CSS 合计** | 364.36 kB (49.94) | **175.44 kB (25.51)** | **-51.8% / -48.9%** |
| **首屏总计** | 1725.2 kB (489.0) | **1061.1 kB (315.3)** | **-38.5% / -35.5%** |

> 首屏 JS 降幅小于 vendor-element 自身降幅，是因为其中包含 vue / pinia / router 等
> 无论如何都要加载的运行时，它们构成了不可压缩的下限。

## 三、触控目标：375/768 从 87 个归零

### 先修了测量口径（否则数字不可信）

原审计脚本把 Element Plus 的内部零件当成独立触控目标来量：
`el-select` 里的 `.el-select__input` 只有 24px 高，但用户实际按到的是外层 `.el-select__wrapper`（32px）。
这类误报会把真问题淹没在噪音里。

改造后的口径：**逐个候选元素向上回溯 4 层，只要任一「交互祖先」已达标，子元素尺寸就不计入**。
同时把 `el-input`、`el-input__wrapper`、`el-slider__button-wrapper` 等真实命中区补进了候选清单。

> ⚠️ 口径变了，桌面端前后数字**不同源**，不能直接相减。这一点在下文表格里已标注。

### 根因不是「没写规则」，而是规则被压住了

项目里早有一兜底：

```scss
@include below-desktop { @include coarse-pointer { button { min-height: 44px } } }
```

但实测 Dashboard 的按钮仍然是 36px。抓计算样式看到 `min-height: 36px` ——
不是没生效，而是**被 scoped 样式覆盖**了：Dashboard 的 `.nav .link`、`.theme-switch button`
和 SideNav 的 `.logout-mini` 都写了 `min-height: 36px`，带上 `[data-v-*]` 后特异性高于裸 `button` 规则。

三类具体缺陷：

1. **scoped 样式击穿**：上述三处的 36px
2. **组件库写死尺寸**：`.el-select__wrapper` 固定 `min-height:32px`、`.el-slider` 固定 `height:32px`，二者都不认 `--el-component-size` 变量
3. **小号按钮**：`size="small"` 依赖 `--el-component-size-small`，原值 36px

修复集中在 `src/styles/global.scss` 的触屏块：兜底规则加 `!important` 压过 scoped 特异性，
另对两个写死尺寸的组件库选择器单独改写。

**桌面为何零回归**：整块规则包在 `(below-desktop) ∩ (pointer: coarse)` 内。
审计脚本每页都会输出指针类型，1024/1440 两档实测均报告 `[鼠标]` ——
媒体查询不匹配，新规则在桌面完全不参与级联。这是可验证的，不是推断。

### 顺带修掉一个桌面可访问性缺陷

审计发现一批 **20px 高**的链接式按钮（`el-button is-link`，默认 padding 只有 2px），
低于 WCAG「目标尺寸（最小）」的 24×24 下限。这在鼠标操作下同样难命中，
对养老场景的使用者尤其不友好。已补 `min-height: 24px`（桌面不追求 44px，避免过度撑高表格行）。

### 实测结果

| 视口 | 指针 | 小触点(<44px) | 低于 24px | 横向溢出 | 不可达内容 |
|---|---|---|---|---|---|
| 375px | 触屏 | 35 → **0** | **0** | **0** | **0px** |
| 768px | 触屏 | 52 → **0** | **0** | **0** | **0px** |
| 1024px | 鼠标 | 166（口径变更，详见注） | **0**（原 36） | **0** | **0px** |
| 1440px | 鼠标 | 166（口径变更，详见注） | **0**（原 36） | **0** | **0px** |

> 桌面 166 个「小触点」是拿触屏的 44px 标准去量鼠标界面的结果，
> 不构成缺陷 —— 关键是其中**已无任何低于 24px 的元素**。
> 桌面端 44px 的追求会显著撑高表格密度，不符合大屏操作的取舍。

## 四、交互体验补强

### 路由过渡 + 懒加载进度条

原先 `App.vue` 的 `router-view` 无过渡、无加载反馈 —— 慢网环境下切换页面是纯白屏，
用户无法区分「在加载」还是「卡死了」。

- **`transition mode="out-in"`**：0.18s 纯透明度淡入淡出。
  刻意不做位移 —— 页面里有 WebGL canvas 和绝对定位图层，`transform` 会促成额外合成层，
  还会让 ECharts 的容器尺寸测量出现亚像素抖动。`prefers-reduced-motion` 由全局统一压制。
- **`RouteProgress.vue`**：顶部 2px 渐变进度条。**延迟 120ms 才出现**，chunk 命中缓存时不闪。
  刻意用无限 CSS 动画表达「进行中」，而不是伪造 0→90% 的假进度 —— 真实下载进度拿不到。

风险点：`out-in` 模式配合异步组件是已知易踩的坑，可能留下空白。
已实测 8 组客户端路由跳转（点侧栏菜单，非 `page.goto`），
每跳都对 DOM 节点数、内容区 opacity、标题、路径做了断言，**全部正常，0 错误**，且确实观察到进度条出现。

### 时钟重渲染下沉

顶栏时钟原先是 Layout 自己的响应式状态，每秒触发 Layout 渲染函数重跑，
模板里的 SideNav（10 个菜单项）、抽屉、`<component :is>` 都要跟着创建 vnode 参与 diff —— 页面挂着不动也在持续产生开销。

拆出 `LiveClock.vue` 后，每秒只有这个叶子组件重渲染，Layout 子树完全不动。

## 五、工程质量：把口径固化成脚本

| 脚本 | 作用 |
|---|---|
| `scripts/check-element-imports.mjs`（新增） | 静态比对模板用到的 `<el-xxx>` 与注册清单（**含弹层内部的不渲染组件**）；同时禁止绕过插件入口的根导入 |
| `scripts/smoke.mjs`（增强） | 新增「未注册组件」检测（Vue 只发 warn 不发 error，原本抓不到）；新增**弹层交互阶段** |
| `scripts/responsive-audit.mjs`（修正口径） | 触控目标按真实命中祖先判定；每页输出指针类型，用于证明桌面未受新规则影响 |

**为什么要加弹层阶段**：`el-dialog` / `el-drawer` 默认 Teleport 且不挂载，
遍历路由时它们压根没渲染 —— 按需引入漏注册这类组件，路由检查一个都抓不到。
这是「静态清单对得上、运行时却静默降级」的唯一盲区。现已覆盖 3 个弹窗 + 1 个移动端抽屉，均实测打开且有内容。

调试过程中还修了两处**测试脚本自身的 bug**（不是产品缺陷，但会误导结论）：
用 `.el-button--primary` 定位「新增」按钮时命中的是侧栏「退出」，点了直接跳走，看起来像「弹窗打不开」；
以及 `rm -rf` 被沙箱拦截导致 Vite 预构建清理失败。

## 七、补遗：园区总览工具栏被面板遮住（用户实测发现）

上线前用户在 `/overview` 截图里发现：三维工具栏只剩「号 / 暂停提示 / ⟳」露在面板右侧，
「全楼 / 1F / 2F / 3F / 显示房号」整段不见了。

### 根因：层叠上下文让 z-index 失效

```scss
.stage { position: absolute; inset: 0; z-index: 0; }   /* ← 创建了层叠上下文 */
.campus-tools { position: absolute; top: 12px; left: 12px; z-index: 12; }  /* 只在舞台内部生效 */
.hud-summary { position: absolute; top: 14px; left: 14px; width: 268px; z-index: 10; }  /* 舞台的兄弟节点 */
```

`.campus-tools` 的 `z-index: 12` 看起来比面板的 10 大，但它**只在 `.stage` 这个层叠上下文内部参与比较**；
对外整个舞台就是 0，被 10 的面板整个压住。工具栏定位又恰好和面板同在左上角，
于是前 270px 宽的按钮全部被埋住，点击也落不到 —— 楼层筛选实际处于不可用状态。

这类 bug 之前的所有指标都抓不到：不溢出、可达、尺寸也够。它是一种独立的缺陷形态 —— **遮挡**。

### 修复

由宿主页面用 CSS 变量把工具栏起点让到面板右侧，组件保留默认值以维持独立复用：

```scss
/* Overview.vue */
.stage {
  --tools-left: 296px;                       /* 14 + 268 + 14 */
  --tools-max: calc(100% - 296px - 12px);
  &.has-detail { --tools-max: calc(100% - 296px - 328px - 12px); }  /* 右侧详情打开时同步收窄 */
}

/* Campus3D.vue */
.campus-tools { left: var(--tools-left, 12px); max-width: var(--tools-max, calc(100% - 24px)); }
```

窄屏（<768px）面板下沉为文档流、舞台全宽，变量复位为贴左。
`has-detail` 由 `activeDetail` 驱动：详情面板弹出时工具栏可用宽度同步收窄，
否则平板宽度下工具栏右端会钻进详情面板底下。

### 新增「遮挡检测」指标

既然指标体系漏了这一类，就把它补上 —— 在 `responsive-audit.mjs` 里对每个可交互元素
取中心 + 四个边缘采样点，逐个问 `document.elementFromPoint`；
一个点都没命中「元素自身或其后代」就判定为被遮挡，与用户实际能否点中完全一致。

配套排除三类误报源（都是实测踩出来的）：

| 误报源 | 表现 | 排除方式 |
|---|---|---|
| 滚动/裁剪 | 按钮被 `overflow:auto` 面板滚出可视区，命中"穿透"到 canvas（面板背景是 `pointer-events:none`，不参与命中） | 元素 rect 超出任一裁剪祖先的 client box 则跳过 |
| 组件库内部件 | `el-select__input` 上面永远浮着自己的 placeholder | 排除 `.el-select__input` / `.el-input__inner` 等内部零件 |
| 固定列克隆 | el-table 固定列会把操作列克隆一份浮在原位 | 覆盖物内部存在同标签同文案的克隆则视为命中 |

### 实测（修复前 → 修复后）

| 视口 | /overview 被遮挡 | 全站被遮挡 |
|---|---|---|
| 375px 触屏 | 5 → **0** | **0** |
| 768px 触屏 | 0 → **0** | **0** |
| 1024px 鼠标 | 5 → **0** | **0** |
| 1440px 鼠标 | 5 → **0** | **0** |

修复后实测工具栏 7 个按钮在 1440 / 1024 / 768 三档全部可点；
详情面板打开时工具栏与详情左缘间距 182px / 26px / 26px，均无重叠。

> 这一条是用户肉眼发现的，不是指标体系发现的 —— 因为之前根本没这项指标。
> 这也说明：**指标只能覆盖你想得到的问题形态**，真机/真人验收不可省。

## 八、已知限制与后续建议

1. **桌面 44px 未追求**，属有意取舍：需要在点击精度与表格信息密度之间权衡，建议维持 24px 下限。
2. **`vendor-echarts` 1.48MB 仍是最大 chunk**，全站占比最高。若做进一步优化，
   建议先按页面实际用到的图表类型做 ECharts 按需引入（`echarts/core` + 按需注册组件），
   预估同样有接近一半的下降空间 —— 本期未动，因为它涉及改动 6 个页面的 import 方式，风险量与本次不同。
3. **北京服务器尚未发布**。当前 `dist/` 仍是旧产物，`dist-after-element/` 为新构建。
   发布前建议：先用 `dist-after-element` 在线比对一轮公网首屏（此前记录约 10.3s），确认收益落在实处。
4. 本期两个审计脚本的触控口径已变更，**历史报告不可与新报告直接相减**，跨期对比请统一用 `[触屏]/[鼠标]` 标注后的数据。
