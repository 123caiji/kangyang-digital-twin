## 二、基线：指标"全绿"但页面不可用

把两页补进 `scripts/responsive-audit.mjs` 后，基线数据出乎意料地好看：
375/768 触屏小触点 0、横向溢出 0、被遮挡 0 —— **但 375px 截图一看，页面根本没法用**：

- `/devices`：8 列宽表塞进 375px，用户只能看到 设备ID/名称/类型，关联房间、住户、区域、
  **状态、操作按钮**全部要横向滚动才能碰到；删除设备要先滚到最右边。
- `/audit`：8 列表格同样情况；4 个统计卡挤一行。

这再次验证了二期报告的教训：**指标清零 ≠ 没问题，只等于"清单里的问题"没了**。
横向溢出为 0 是因为 el-table 自带内部横向滚动（属于"可滚动溢出"，不算页面缺陷）——
指标正确地没报它，但"要不要横向滚动才能点删除"是可用性问题，只有截图和真人能回答。

### 桌面端反而有一个硬缺陷

`unreachableUnlocked`：`/devices` 在 1024px 为 **196px**、1440px 为 **64px**。

根因是页面骨架：Layout 的 `.content` 在桌面端是 `overflow: hidden`，
每个页面自己负责滚动（既有范式是根节点用 `.page.page-scroll`）。
而这两个新页面的根节点是 `.device-page` / `.audit-page`（只有 padding，没有滚动能力），
于是**表格超出视口的部分在桌面上被直接裁掉**——不是滚动不到，是永远看不到。
触屏档（<1024）因为 `.content.is-scroll` 接管了滚动，所以恰好是 0，把问题挡住了。

## 三、修复内容

两个页面统一改用与 数据管理/用户管理 完全一致的页面骨架：

```
.page.page-scroll（桌面定高内滚 / 窄屏交还 Layout）
├─ .toolbar.glass-panel        主操作 + 刷新
├─ .stats-row                  统计卡（grid，窄屏自动换行）
├─ 桌面/平板：.table-wrap + el-table(height=100%)
├─ 手机：MobileCardList（复用 .rec-card 共用套件）
└─ el-dialog（窄屏 92vw，DeviceManage 为 fullscreen）
```

### IoT 设备管理（DeviceManage.vue）
- 表格 ↔ 卡片双形态：手机端 `MobileCardList`，字段含设备ID/类型/房间/住户/区域/状态/最后在线，操作三按钮直达。
- **列序调整**：「状态」从第 7 列前移到第 4 列——窄桌面（1024）下它原本和操作列一起被挤进横向滚动区，
  而巡检时最关心的就是在线状态。
- 操作列从 3 个 `size="small"` 块状按钮（280px）改为链接式按钮（186px，`fixed="right"`），窄桌面下操作始终可见可点。
- 弹窗窄屏 `fullscreen` / 桌面 520px；表单 label 窄屏顶对齐。
- 补齐：空状态（暂无设备）、加载骨架、**必填校验**（设备ID/设备名称，创建时前置拦截）、
  删除/重置Token 的失败反馈（原来 catch 静默吞掉所有错误，包括接口 500）。
- 统计卡由 flex 改 grid，375px 数字不再被压扁。

### 安全审计日志（AuditLog.vue）
- 同样的表格 ↔ 卡片降级；卡片标题是操作类型（登录/账号锁定/…），详情（JSON 报文）在卡片里
  `overflow-wrap: anywhere` 完整可读，不再被 tooltip 截断。
- **补了筛选**：操作类型（选项从真实数据归纳，接口新增动作不用改前端）+ 状态（成功/失败/拦截）。
- **补了分页**：接口上限 100 条，客户端分页（10/20/50 每页），筛选后页码越界自动回落到第 1 页。
- 修复 `default-sort` 写成字符串的 bug：原来写的是
  `default-sort="{ prop: 'id', order: 'descending' }"`（普通属性传的是字符串，Element Plus 无法解析），
  改为 `:default-sort` 绑定对象后，默认按 ID 降序才真正生效——最新日志排在最前。
- 统计卡 grid：手机 2×2，数字不再挤压。
- 硬编码面板底色 `rgba(40,30,50,.55)` 统一改走 `glass-panel` / 设计令牌。

### 组件注册修复（静默降级类 bug）
`DeviceManage` 的 Token 弹窗用了 `<el-alert>`，但 `ElAlert` 从未注册——
正是二期报告说的"静态清单对得上、运行时却静默降级"形态：Vue 只发 warn 不发 error，
页面不崩，用户看到的是一段没有样式没有图标的裸文本。
`scripts/check-element-imports.mjs` 一跑便抓到（这两个页面加入后没人重跑过守卫）：

```
✗ 以下组件在模板中使用，但未在 plugins/element.js 注册：
   ElAlert   出现于: src/views/DeviceManage.vue
```

修复：`plugins/element.js` 增补 import + style + COMPONENTS，`vite.config.js` 的
`optimizeDeps.include` 同步登记深路径。守卫复检 29/29 对齐。
运行时实测（注册临时设备 → Token 弹窗）：`.el-alert` 真实渲染 486×56、有内边距，临时设备已删除。

### 审计与冒烟清单同步
- `responsive-audit.mjs`：PAGES 增加 `/devices`、`/audit`（此后每轮全站实测都是 12 页）。
- `smoke.mjs`：ROUTES 增加两页；OVERLAYS 增加「IoT设备 · 注册弹窗」（只开不保存，不产生脏数据）。

## 五、已知边界与后续建议

1. **权限链路现状自洽**：两页菜单挂 `users` 权限，而种子数据里 editor/viewer 均无 `users`，
   后端 `/api/iot/devices` 与 `/api/audit/logs` 也限 admin —— 实际不会出现"看得到菜单却 403"。
   但若管理员日后给 editor 手工勾上 `users`，这两页会出现菜单可见、数据 403。
   建议二选一：菜单改挂独立 `admin` 语义，或后端放宽到 `auth()` + 前端按权限隐藏操作列。
2. **`vendor-echarts` 1.48MB** 仍是最大 chunk（本次未动，与二期结论一致），按需注册仍是下一个优化点。
3. **未发布**：`dist/` 仍是旧产物，本次构建在 `outputs/r4-release/`；发布前建议先在预览环境过一轮。
4. 桌面 44px 触控标准维持二期取舍（只保 24px 下限），避免撑高表格行。
